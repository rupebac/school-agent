# Source and regression review — 2026-10-20

This review exercised the local working tree, including the previously implemented
Google configuration, Calendar backfill and integration diagnostics. The backend
and frontend fixes below were deployed on 2026-10-20 after the local verification.
The test fixtures used no production credentials, family records, school submissions,
Google Calendar mutations or WhatsApp messages.

The review found reproducible defects despite a green baseline of 394 backend and
84 frontend tests. The initial pass added 22 backend tests, two frontend tests, three worker
network-policy tests and one privacy-scanner regression; the follow-up adds further
security, persistence, resource, recovery and translation regressions. This is a broad source
review and regression exercise, not a claim of complete statement coverage or a
production penetration test.

## Fixed findings

Severity is the reviewer's assessment of impact and prerequisites, not a CVSS score.
Paths refer to `backend/src/main/kotlin/de/schoolagent/` unless otherwise specified.

| Priority | Defect and observable consequence | Correction and evidence |
| --- | --- | --- |
| High | Manual login retained the pre-authentication session ID. | `security/AuthController.kt` invokes the session-fixation strategy. HTTP integration test verifies rotation and rejection of the old session. |
| High | Existing sessions retained privileges after an account was deleted, demoted or its password changed; remembered-login tokens survived changes. | `CurrentAccountFilter` checks a password/role stamp against the current account. Account mutations revoke persistent tokens. Integration tests cover demotion, deletion and password reset with remembered login. |
| High | Ordinary parents could reach shared WhatsApp configuration and diagnostic endpoints, including sensitive settings. | `/api/whatsapp/**` now requires ADMIN except the separately verified webhook. The UI hides admin controls from parents; API authorization tests enforce the boundary. |
| High | Webhook POSTs were accepted without signatures when no App Secret was configured. | Incoming deliveries fail closed unless a configured secret verifies the signature; constant-time comparison. Tests cover missing secret, invalid signatures and signed deliveries. |
| High | Matching only a phone-number suffix could associate an incoming WhatsApp sender with another parent's account. | Full international digits must match exactly and uniquely; ambiguous results are rejected. Synthetic collision tests cover the active WhatsApp lookup. |
| High | Omitting the child identifier exposed the legacy Google connection to ordinary parents. | Null-child Google status, authorization, disconnect and setup routes now require ADMIN. Assigned-child routes retain their existing access checks. HTTP integration test covers the legacy routes. |
| High | Link investigation could access private network destinations, including redirects and browser subrequests; JavaScript could initiate non-read requests. | Public-network policy is enforced at the HTTP socket DNS resolver and the worker's request transport. Browser requests permit GET/HEAD only, block WebSockets and service workers, and bound request count, bytes and concurrency. Boundary and blocked-request tests cover the policy. The follow-up also applies this transport policy to Elternportal; see the follow-up table. |
| Medium | Browser-generated evidence referenced a made-up source ID instead of the persisted source, violating foreign-key integrity. | `InvestigationService` links evidence to the saved JavaScript source. Regression test verifies that ID. |
| Medium | URL deduplication was global, so a link investigated for one case could suppress evidence for another child/case. | Web source deduplication keys include the case ID. Regression test uses the same link in two separate cases. |
| Medium | URL canonicalization encoded existing `%` escapes a second time, breaking form and signed links. | `Links.canonicalize` preserves raw path/query escapes while removing tracking fields. Regression test covers escaped tokens. |
| Medium | Quotes, backslashes and control characters could produce invalid JSON in action, requirement, feedback and family-rule records. Repeated feedback reused a unique rule key. | Serialize structured data with Jackson, parse stored rule text as JSON, and allocate unique feedback rule keys. PostgreSQL integration tests exercise special characters and repeated feedback. |
| Medium | Spring MVC's active Jackson version lacked its Kotlin module, so omitted default DTO fields could produce HTTP 400 before authorization or business logic ran. | Add the Jackson 3 Kotlin module alongside the Jackson 2 module used by existing services. The empty Calendar-setup request reaches the expected authorization result; API and full suites pass. |
| Medium | Two different exams of the same type on the same day could be collapsed into a single event. | Reasoning deduplication also compares titles and, during extraction collapse, times. Regression test preserves Mathematics and English exams on the same date while existing paraphrase tests still pass. |
| Medium | A reminder preference such as `9:00` was accepted but never matched by the scheduler. | Parse `H:mm`, normalize saved preferences to `HH:mm`. Scheduler regression verifies delivery within the intended window. |
| Medium | Calendar cleanup failures for old/cancelled events were excluded from retry selection; missing remote events caused repeated delete failures. | Retry selection includes failed removals even for past dates. HTTP 404/410 deletes complete successfully. Repository, projection and HTTP-client tests cover cleanup. |
| Medium | Calendar projection could run before dedicated-calendar setup, and token HTTP failures could escape normal retry handling. Date changes made while disconnected could retain SYNCED status. | Defer projection while the target is `primary`; translate token transport failures into safe typed failures; mark changed events pending. Targeted setup/token tests and the full reasoning/projection suite pass. |
| Medium | Frontend login completed before the profile request, causing premature navigation and swallowing profile-load failures. | `Auth.login` waits for `/me` in the observable chain. Two tests cover ordering and failure propagation. |
| Medium | Document references allowed malformed paths, and concurrent readers could see a partly written file. | Validate SHA-256 references and publish via a temporary file plus atomic move. Document-store tests cover invalid references and existing storage behavior. |
| Medium | Failed database dumps could leave apparently valid backup files; archive permissions depended on the caller's umask. | `backup.sh` uses umask 077, a temporary archive, gzip verification, atomic publication and failure cleanup. Synthetic success/failure smoke checks passed. |
| Medium | Logs and some transport errors exposed raw exception messages that could contain URLs, provider bodies or sender information. | Reviewed ingestion, scheduler, messaging and transport paths log exception types or safe messages instead. This reduces exposure in those paths; it is not a proof that every future exception is sanitized. |
| Maintenance | Resolved dependencies matched published advisories, and the worker package/image versions were inconsistent. | Refresh the frontend lockfile, pin matching Playwright 1.64.0 package/image, and update Tomcat and both Jackson lines. Re-run suites, builds and dependency scans. |

The session fix follows Spring's requirement for custom authentication to invoke
the session strategy. See [Spring Security session management](https://docs.spring.io/spring-security/reference/7.0/servlet/authentication/session-management.html).
The crawler uses destination validation at connection time in addition to URL
validation, consistent with the DNS and redirect considerations in the
[OWASP SSRF prevention guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

Dependency updates use Tomcat 11.0.26, Jackson 2.21.7 and Jackson 3.1.7.
Upstream references: [Tomcat security fixes](https://tomcat.apache.org/security-11.html),
[Jackson 2.21 releases](https://github.com/FasterXML/jackson/wiki/Jackson-Release-2.21),
[Jackson 3.1 releases](https://github.com/FasterXML/jackson/wiki/Jackson-Release-3.1).
The frontend is a static SPA; an Angular router SSR advisory in its dependency
tree did not establish an exploitable SSR deployment. See the
[Angular advisory](https://github.com/advisories/GHSA-ff3f-86qr-9cv3).

rollout. The optional browser worker remains inactive; its source and sandbox
configuration were updated without enabling the service.

## Limits and rollout notes

OAuth consent, account switching, school-provider HTML changes, real provider
retry behavior and live notification delivery were not tested in this pass.
The follow-up browser checks use a real backend and database, but do not validate
live Google synchronization or school-provider changes. Integration tests use
synthetic data and controlled provider responses. Production load and long-running
soak testing remain operational validation, not a claim made by this test pass.

Configure the WhatsApp App Secret before using incoming
messages, check that stored phone numbers include the country code, and
verify that the portal URL resolves to public addresses and that the optional browser
worker host supports unprivileged user namespaces. Updated account security
intentionally signs out stale sessions after account changes.

Deployment verification covered a full recovery snapshot, successful V31–V33
migrations with all historical checksums unchanged, matching release images,
public health and frontend fingerprint, and bounded Docker logs. The private
environment was preserved. This does not extend the provider-delivery or load-test
claims above.

Keep all raw test/scan logs outside the repository. The public-content scanner's
new network-fixture exception is restricted to exact RFC boundary values in three
specific policy/test files; its regression verifies that other addresses and files
remain blocked. No general privacy or secret-scanning exclusions were added.
